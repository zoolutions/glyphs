# Workflow profile

Everything the shared workflow skills (`/lode:lfg`, `/lode:review-pr`,
`/lode:finish-prs`, `/lode:debug-flaky`, `/lode:tdd`, `/lode:plan`) need to know
about this repository that is not already in `../.claude/rules/` or the rest of
`lode/`.

## Commands

| Purpose | Command | Notes |
|---|---|---|
| fast loop (one file) | `bundle exec rspec spec/glyphs/<name>_spec.rb` | ~2s including load; no network, no services |
| full suite | `bundle exec rspec` | 13 files, 140 examples. No network, no database, no ports — safe in two worktrees at once |
| lint | `bundle exec rubocop lib spec` | what CI's `Lint` job runs; bare `rubocop` (what `rake` runs) also covers `Rakefile` and `glyphs.gemspec` |
| everything | `bundle exec rake` | `spec` then bare `rubocop` — the strictest local gate |
| one CI cell locally | n/a | the matrix is only Ruby 3.4 / 4.0; switch Ruby (`.tool-versions` pins 4.0.5) and re-run the same two commands |
| docs check | `cd docs && bundle exec rubocop && bundle exec rspec` | separate bundle; must be run from `docs/`. The rubocop half currently inspects 0 files: the root `.rubocop.yml`'s `AllCops: Exclude: docs/**/*` is ancestor-merged into the docs run (issue #15), so only the rspec half checks anything |
| docs CSS | `cd docs && bun run build:css` | needed only when new Tailwind classes were added |
| run the app | `cd docs && bin/dev` | a one-line `exec ./bin/rails server` — it does **not** read `Procfile.dev`, so run `bun run watch:css` in a second shell when editing Tailwind classes |
| gem packaging | `bundle exec rake build` | `gem build --strict`, unpacks and prints the file list |

## Branches and PRs

The binding rules are `../.claude/rules/git-workflow.md`; what the shared skills
need on top of them:

- Default branch: `main`. Remote `origin` is `zoolutions/glyphs`.
- Work branches: the rule's `feat/*`, `fix/*`, `refactor/*`, `ci/*`, `chore/*`,
  rooted off fresh `origin/main`. Merged history also shows `issue-<n>-<slug>`
  for a branch that closes a numbered issue.
- Commits: conventional, scoped from the architecture (the rule lists the nine
  scopes). The body says why, and cites `Refs #<issue>` where there is one.
- PR body sections, in order: Summary, Test plan, Deviations & judgment calls,
  Gate.
- Merge policy: squash on `main` once CI is green and the PR is approved. Never
  force-push a published branch; merge `main` forward instead of rebasing.
- Attribution: the user's own rule forbids `Co-Authored-By: Claude`, "Generated
  with Claude Code" and any similar line in commits or PR bodies. The
  `Claude-Session:` line the harness asks for is the only one added.

## Layers

| Layer | Files | Edit rule |
|---|---|---|
| Render path | `lib/glyphs.rb`, `lib/glyphs/icon.rb`, `lib/glyphs/configuration.rb` | owned here; every render must still go through `Glyphs.svg_for` |
| Library components | `lib/glyphs/*_icon.rb` (13) | owned here; one file per library, body is `LIBRARY = :sym` and nothing else |
| Shared tables | `lib/glyphs/icon_reference.rb` | owned here, but canonical — the cops re-key `LIBRARY_TO_COMPONENT` and the scanner reads it. Change it and check both consumers |
| Pruning | `lib/glyphs/source_scanner.rb`, `icon_pruner.rb`, `prune_runner.rb`, `prune_report.rb`, `lib/tasks/glyphs.rake`, `lib/glyphs/railtie.rb` | owned here; destructive, so see `pruning/summary.md` before editing |
| Cops | `lib/rubocop/cop/glyphs/*.rb`, `lib/glyphs/rubocop.rb`, `config/default.yml` | owned here; every option a cop reads must be declared in `config/default.yml` |
| Version | `lib/glyphs/version.rb` | owned by `rake release` — never edited in a feature PR |
| Lockfiles | `Gemfile.lock`, `docs/Gemfile.lock`, `docs/bun.lock` | generated — regenerate, never hand-edit |
| Docs app | `docs/**` | separate bundle; run its commands from `docs/` |
| Built CSS | `docs/app/assets/builds/application.css`, `docs/app/assets/stylesheets/tailwind.sources.css` | generated by `bin/build-css`; committed, but never hand-edited |
| Synced icons | `docs/app/assets/svg/icons/**` (1745 lucide SVGs) | vendored by `rails_icons:sync`; never hand-edit, never hand-delete |

## Shapes

Check a change against these before calling it done:

- A name given as a `Symbol` and as a `String`, underscored and dasherized.
- `variant:` absent (library default), a literal, dynamic (skipped everywhere),
  `""` and `"."` (both mean no variant), and a library whose default variant is
  `nil` — five of the thirteen.
- A library with no `fallback_icons` entry, and a fallback whose own file is
  missing (both re-raise the *original* error).
- `keep_icons` as a flat array, as a `{ library => [...] }` hash, as an empty
  per-library array, and with fnmatch globs.
- A library rendered only with literals, only dynamically, and both — the three
  cases `DynamicHarvest` distinguishes.
- A template call with a nested paren in the argument tail
  (`icon("save", class: cn("a"), from: :lucide)`).
- A Ruby file that does not parse (Prism returns a partial AST and no warning).
- The cop's three directory states: absent, present-but-empty, populated.
- Rails present and absent — it changes `raise_on_missing`'s default,
  `PruneRunner#default_root`, and whether the Railtie loads at all.
- `cache_svgs` on and off.
- A dry run and a real one (`PRUNE=1 GLYPHS_PRUNE_ICONS=1`).
- Ruby 3.4 and Ruby 4.0.

## Constraints

Reviewer suggestions that are wrong in this repository.

| Suggestion | Why it is wrong here |
|---|---|
| Gitignore `docs/app/assets/stylesheets/tailwind.sources.css` | It is regenerated before every build and excluded from the image; committing it is the docs-kit fleet convention. See `review/docs-site.md` |
| Bump `lib/glyphs/version.rb` in this PR | `rake release[X.Y.Z]` owns the version, the tag and the publish, and releases land directly on `main` |
| Add `# rubocop:disable` to get the `Lint` job green | Fix the offence; a targeted disable is acceptable only when RuboCop is demonstrably wrong |
| `rescue nil` / bare `rescue` / `&.` / `return if x.nil?` to silence an error | These hide bugs. Fix the earliest point that prevents the error — see the symptom-to-cause table below |
| Speed the scanner up by skipping files or whole globs | Under-scanning silently prunes referenced icons (`.claude/rules/performance.md`) |
| Drop the `@svg_cache_mutex` or swap in an unsynchronized structure | `svg_for` is called concurrently under a threaded server |
| Declare `prism` in the gemspec | It is a Ruby default gem at the `>= 3.4` floor; the runtime dependency budget is three gems |

The fix for a symptom is almost never where the symptom surfaced:

| Symptom | Where the fix belongs |
|---|---|
| An icon renders blank | the `Glyphs.svg_for` resolution / variant path, not a `rescue` in the component |
| A referenced icon got pruned | `SourceScanner`'s dynamic-call harvesting, not a `keep_icons` band-aid |
| A cop autocorrect produces invalid Ruby | the corrector's replacement, not disabling the cop |
| A missing-icon crash in production | the `raise_on_missing` / `fallback_icons` path, not a caller-side `&.` |

## Docs

- User-facing docs live in `docs/app/views/docs/pages/`, one `DocsUI::Page`
  subclass each, and a page is routed only if `docs/app/models/doc.rb` has a
  matching `page "…"` line. `README.md` documents the same public surface and
  must not contradict it.
- Changelog: `CHANGELOG.md`, new entries under `## [Unreleased]` in an
  `### Added` / `### Changed` / `### Fixed` subsection.
- A change to a component, a config option, a cop option, or the prune task
  always updates the matching docs page, `README.md` and `CHANGELOG.md` in the
  same PR.
- `docs/Gemfile.lock` pins `glyphs (X.Y.Z)` through `path: ".."` and drifts after
  a version bump; `rake release` runs `cd docs && bundle install` for exactly
  this reason. If it is ever out of step, regenerate it there — do not hand-edit.

## CI

- Workflows: `main.yml` (on push to `main` and every PR — `Lint`,
  `Gem Tests (Ruby 3.4)`, `Gem Tests (Ruby 4.0)`, `Docs Lint`, `Docs Tests`),
  `release.yml` (on a published Release — test, build+verify, RubyGems trusted
  publishing with Sigstore, upload assets), `publish-tag.yml`
  (`workflow_dispatch` with a `tag` input, to republish a tag), `deploy-docs.yml`
  (the docs site, on a published Release or `workflow_dispatch`).
- Matrix: Ruby 3.4 and 4.0 for the gem specs, `fail-fast: false`; every other job
  is Ruby 4.0. Cells differ from local only in the Ruby version.
- Fetch a failure: `gh run view <RUN_ID> --job=<JOB_ID> --log-failed`.
- Failure signatures worth recognising before reading further: `Errno::ENOENT`
  or a missing SVG means a fixture outside `spec/fixtures` (the specs point
  `Icons.config.base_path` there) or a library/variant/name that is not on disk;
  an `expect_offense` / `expect_correction` mismatch means the cop's annotated
  source, message or autocorrection drifted from the cop; `gem build --strict`
  rejects an open `>=` dependency. RuboCop offences are usually `bundle exec
  rubocop -A <file>`.
- Green means all five `main.yml` check runs.
- Known not-this-branch failures: none recorded.
- Shared or rate-limited services: none — nothing in CI reaches the network
  beyond the package registries, so PRs can run concurrently.

## Flake sources

- **Process-global memos plus `config.order = :random`.** `Glyphs.configuration`,
  `Glyphs`'s `@svg_cache`, and `IconResolution`'s `@warned_messages` all outlive
  an example. The first two are reset in `spec/spec_helper.rb`'s global `before`
  and the third in `icon_resolution_spec.rb`'s own `before`. A new memo without a
  reset is the flake this repo produces.
- **`IconResolution.@available_icons_cache` has no reset at all** — harmless
  today because no spec creates an icon directory mid-run, but a spec that did
  would be order-dependent.
- **Global spies on `File.read`** (`icon_spec.rb`'s caching examples count reads
  process-wide) — any extra render inside the same example changes the count.
- Not flakes: a failure on one Ruby version only is a version-specific bug, and
  nothing in the suite touches the network, the clock or a port.

## Conflicts

| File | Rule |
|---|---|
| `lib/glyphs/version.rb` | take the base's; a feature branch should never have bumped it |
| `CHANGELOG.md` | union under `## [Unreleased]`, keeping both sides' bullets most recent first and not duplicating the `### Added`/`### Fixed` subheads |
| `Gemfile.lock`, `docs/Gemfile.lock` | take the base's, then `bundle install` at the root or in `docs/` |
| `docs/bun.lock` | take the base's, then `cd docs && bun install` |
| `docs/app/models/doc.rb`, `docs/config/routes.rb` | append-only, base order first |
| `lib/glyphs/icon_reference.rb` (`LIBRARY_TO_COMPONENT`) | both sides appended — keep both rows, and check both `lib/glyphs/*_icon.rb` files survived too |
| `config/default.yml` | keep both cops' option blocks; a dropped key becomes a `does not support <param>` warning on every run |
| `docs/app/assets/stylesheets/tailwind.sources.css`, `docs/app/assets/builds/application.css` | take either side, then regenerate with `cd docs && bun run build:css` |
| `spec/fixtures/**` | add a second fixture rather than merging two shapes into one file |

## Verification

- The manual check a user would do: `cd docs && bin/dev`, open a page that
  renders icons, and confirm the SVGs appear. For a pruner change, run the dry
  run from `docs/` (`bin/rails glyphs:prune_icons`) and read the report — it
  prints per-library kept/deleted counts without touching a file.
- Stress iterations for an order-dependence proof: 20 runs with different seeds
  (`bundle exec rspec --seed <n>`); this repo's non-determinism is ordering, not
  timing, so repeating one seed proves nothing.
- Where evidence goes: `lode/tmp/` (git-ignored), unless the PR needs an
  auditable trail.
