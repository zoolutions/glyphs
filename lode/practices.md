# Practices

The binding rules live in `../.claude/rules/` — `coding-style.md`,
`git-workflow.md`, `testing.md`, `performance.md`, `agents.md`. This file adds
only what those do not state. Rules with a specific proof live in `review/`.

## Deleting files is different from rendering them

The pruner is the only destructive code in the gem, and every design choice in
it follows from one asymmetry: keeping an icon nobody renders wastes a few
kilobytes, deleting one an app renders is a production `Icons::IconNotFound`.
So:

- **Harvest, then keep, then verify.** A name that cannot be read off a literal
  call site is harvested as an *advisory* keep, never as a confirmed reference.
  Advisory keeps are kept if present and never asserted afterwards; confirmed
  references are both. Blurring the two makes `verify!` fail on a CSS class that
  happened to look like an icon name.
- **Evidence is per library.** Any guard that decides "is this library in use?"
  must key off library-specific evidence. A flat `keep_icons` list matches
  everywhere and so proves nothing about any particular library.
- **Say why, on stderr, and keep going.** The pruner warns and skips a group it
  refuses to touch; the scanner warns and skips a file it cannot read. Neither
  aborts the run.

## Adding a library is two edits, not one

`Glyphs::IconReference::LIBRARY_TO_COMPONENT` is the canonical map — the cops
re-key it and the scanner reads it — but the component class still has to exist
as its own `lib/glyphs/<name>_icon.rb` file. Adding a row without the file gives
the cops a component the kit cannot render; adding the file without the row
makes the scanner blind to it, and the pruner will delete its icons. The
`Glyphs/IconResolution` `DEFAULT_LIBRARIES` table is a *third* list and covers
only five of the thirteen on purpose — extend it only when the gem can state the
library's default variant confidently.

## Process-global state needs a reset, and the reset needs a caller

Five memos outlive a single object: `Glyphs.configuration`, `Glyphs`'s
`@svg_cache`, `IconReference.@component_to_library`,
`IconResolution.@warned_messages` and `IconResolution.@available_icons_cache`.
The first two have a reset method and a caller in `spec/spec_helper.rb`'s global
`before`; `@warned_messages` has `reset_warnings!` and a caller in
`icon_resolution_spec.rb`. `@component_to_library` needs none — it inverts a
frozen constant, so it cannot go stale. `@available_icons_cache` has no reset,
which is fine only because a directory listing does not change inside one
RuboCop run. Anything new that memoizes across instances gets a reset in the
same commit, and a `before` hook that calls it.

## A universal claim in prose is a claim about a constant

`README.md` and the docs pages describe "every library", "all the cops", "the
variants". Before writing one, open the constant and count: `LIBRARY_TO_COMPONENT`
(13), `LEGACY_HELPERS` (5), `DEFAULT_LIBRARIES` (5), `ICONIFY_PATTERN`'s
alternation (3), `DEFAULT_FALLBACK_ICONS` (3), `KNOWN_LUCIDE_RENAMES` (3). A
sentence that says "every" where the code says "five" is the defect this repo
produces most.

## Prose lives in two places at once

Every user-facing behaviour is documented in `README.md` *and* in the matching
page under `docs/app/views/docs/pages/`. A change to a flag, a default, or an
env-var gate updates both in the same PR, plus a `CHANGELOG.md` entry under
`## [Unreleased]`. Transcripts and messages quoted in either must be the exact
string the code prints.

## Generated files that are committed

`docs/app/assets/stylesheets/tailwind.sources.css` is generated and committed on
purpose (`review/docs-site.md`). Anything else generated is either regenerated by
a task (`Gemfile.lock`, `docs/Gemfile.lock` — `rake release` refreshes both) or
kept out of the image (`.dockerignore`). Never hand-edit a lockfile.
